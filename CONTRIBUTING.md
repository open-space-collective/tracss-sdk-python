# Contributing to tracss

Thanks for your interest. This doc explains how the repo is structured and what kind of contributions make sense.

## What's generated vs. hand-written

Almost everything under `sdks/python/tracss/` is **auto-generated by Fern** and gets overwritten on every `fern generate` run. The exceptions are files listed in `sdks/python/tracss/.fernignore` - see that file for the full list with explanations.

If you send a PR that edits generated files directly, it will be closed. The right place to change SDK behavior is:
- `fern/sdks/` - method names, parameter overrides, SDK surface
- `fern/generators.yml` - generation config (pydantic settings, client class names, etc.)
- `sdks/python/tracss/client.py` - auth logic, env var defaults

## Setup

```bash
uv sync                             # install all workspace deps
pre-commit install                  # wire the git hooks (ruff + mypy on commit)
npm install -g fern-api@5.46.0      # Fern CLI
npm install -g @stoplight/prism-cli # Prism (for integration tests)
```

## Changing the SDK surface

If you want to rename a method, add a parameter override, or adjust the client hierarchy:

```bash
# 1. Edit the relevant fern/sdks/*-overrides.yaml file
# 2. Validate
make check

# 3. Regenerate (both steps are required)
make generate
make post-generate   # patches org-name bug, wires __version__, adds RawResponse export

# 4. Run tests
make test
make prism-all   # in a separate terminal
make integration

# 5. Commit everything: the override change + the regenerated sdks/python/ diff
git add fern/sdks/ sdks/python/
git commit -m "..."
```

> **Why `make post-generate` is required:** `fern generate` alone leaves the generated code in a broken state — the test file contains an invalid Python identifier (`open-space-collective`) from the Fern org name, `__version__` is not wired into `__init__.py`, and `RawResponse` is not exported. `make post-generate` applies sed patches and re-runs ruff to fix all of this. Skipping it will cause `make test` to fail.

## Updating OpenAPI specs

```bash
make specs              # fetches + shows what changed
make check              # validate fern config against new specs
make generate           # regenerate
make post-generate      # required — see note in "Changing the SDK surface" above
make test && make integration
```

Commit `fern/openapi/` + `sdks/python/` together.

## Working on the auth client

`sdks/python/tracss/client.py` is the only file you can freely edit. It's protected by `.fernignore`.

After editing:
```bash
make lint
make typecheck
make test        # unit tests mock the Okta endpoint with respx
```

## Maintaining the format-dispatch wrappers

### Why they exist

The TraCSS metadata API returns CCSDS KVN (`text/plain`) by default when no
`format` query parameter is supplied. Fern's parser always calls `.json()` on
the response, so any non-JSON body causes `ApiError(status_code=200, body=<KVN text>)`.

`client.py` works around this with a thin wrapper hierarchy that:
- injects `format="json"` when the caller doesn't supply one, so the default
  path always returns a typed response object
- catches `ApiError(status_code=200)` when a non-JSON format is explicitly
  requested (e.g. `format="KVN"`) and returns `e.body` as a plain `str`

`bulk_data` and `subscriber` return JSON only and need no wrapping.

### Class hierarchy

```
MetadataClient
└── _MetadataWithJsonDefaults       (overrides .cdm / .ocm / .tip_reports)
     ├── cdm          → _JsonCdmClient        (subclass of CdmClient)
     ├── ocm          → _JsonOcmClient        (subclass of OcmClient)
     └── tip_reports  → _JsonTipReportsClient (subclass of TipReportsClient)
```

Each class has an async mirror: `_AsyncMetadataWithJsonDefaults`,
`_AsyncJsonCdmClient`, etc.

Sync wrapper methods use `_call_or_raw(super().method, **kwargs)`.
Async wrapper methods use `await _async_call_or_raw(super().method, **kwargs)`.

### Which endpoints are currently wrapped

| Endpoint | `format` param? | Wrapped? | Return annotation |
|---|---|---|---|
| CDM `list` / `list_v1` | yes (defaults to KVN) | yes | `ListCdmResponse \| str` |
| CDM `list_by_operational_batch` / `_v1` | no | yes (JSON injection only) | typed (no `\| str`) |
| OCM `list` / `list_v1` | yes (defaults to KVN) | yes | `ListOcmResponse \| str` |
| OCM `list_by_operational_batch*` | no | no (JSON-only in spec) | n/a |
| TIP reports `list` | yes (defaults to KVN) | yes | `Any` (base returns `Any`) |

### When the API changes

**New `list`-style method in an existing family (CDM, OCM, TIP):**
1. Add a wrapper method to `_JsonXxxClient` and `_AsyncJsonXxxClient` using
   `_call_or_raw` / `_async_call_or_raw`.
2. Import the new response type from `metadata/<family>/types/` into
   `client.py` (under `TYPE_CHECKING`).
3. Annotate the method `-> NewType | str` and add `# type: ignore[override]`
   (the return-type widening is intentional - see the `_JsonCdmClient`
   docstring for the full explanation).

**New batch or JSON-only method (no `format` param):**
1. Add a wrapper method using `_call_or_raw` for `format=json` injection.
2. Annotate with the typed return directly (no `| str`, no `# type: ignore`).

**New API family** (e.g. a `conjunction_reports` sub-client):
1. Create `_JsonConjunctionReportsClient(ConjunctionReportsClient)` following
   the `_JsonCdmClient` pattern (one method per list endpoint).
2. Add a `conjunction_reports` property to `_MetadataWithJsonDefaults` (and
   the async variant) that returns the wrapper.
3. Apply the same annotation rules from the cases above.

**Endpoint loses or gains a `format` param** (upstream API change):
- If it gains one and the API defaults to KVN, the endpoint now needs
  wrapping - add a wrapper method.
- If it loses the `format` param, the wrapper method can be removed and the
  generated sub-client used directly.

### No automated guard

No test checks whether a metadata endpoint that should be wrapped actually is.
When reviewing a spec-refresh PR, manually scan the diff for `format` query
parameters in `fern/openapi/metadata/openapi.json`. If a new endpoint has one
and the API default is not JSON, a wrapper is needed.

## Tests

| Layer | Command | What it needs |
|---|---|---|
| Unit | `make test` | nothing |
| Integration | `make integration` | `make prism-all` running |
| Smoke | `make smoke` | real `TRACSS_CLIENT_ID` + `TRACSS_CLIENT_SECRET` |

Unit tests mock everything with `respx`. Integration tests use Prism as a mock server. Smoke tests hit the live TraCSS API.

## PR checklist

- [ ] `make lint` passes
- [ ] `make typecheck` passes
- [ ] `make test` passes
- [ ] `make generate` + `make post-generate` run and output committed (if Fern config changed)
- [ ] Code of conduct acknowledged

## Cutting a release

Releases are automated via [release-please](https://github.com/googleapis/release-please).
Every conventional commit merged to `main` is tracked. Release-please maintains
a rolling "Release PR" that bumps the version in `sdks/python/pyproject.toml`,
updates `CHANGELOG.md`, and creates a `vX.Y.Z` tag when that PR is merged.
The `publish.yml` workflow then fires on the tag automatically.

**Flow:**
1. Merge conventional commits to `main` (`feat:`, `fix:`, `chore:`, etc.).
2. Review and merge the release-please PR titled `chore: release X.Y.Z`.
3. `publish.yml` publishes to PyPI and creates a GitHub release.

### Release candidate

For a release candidate, push a tag manually with a `-rc` suffix. The workflow
publishes to TestPyPI and marks the GitHub release as pre-release:

```bash
git tag v0.2.0-rc1
git push origin main --tags
```

### Required secrets

Publishing uses **OIDC trusted publisher** (`id-token: write` in the workflow). No
`PYPI_TOKEN` or `TEST_PYPI_TOKEN` is required or used.

| Secret | Used for |
|---|---|
| `FERN_TOKEN` | `ci.yml` `generate-check` job; `spec-refresh.yml` SDK generation |
| `RELEASE_PLEASE_TOKEN` | `release-please.yml` — creating the release PR and tagging. Falls back to `GITHUB_TOKEN`, but that prevents CI from running on the resulting PR. |
| `GH_PAT` (optional) | `spec-refresh.yml` — spec-refresh PR creation. Falls back to `GITHUB_TOKEN`; without a PAT, CI must be triggered manually on spec-refresh PRs. |

## Code style

Ruff handles formatting and linting. Mypy handles types. Both run on pre-commit and in CI. The rules are in `pyproject.toml`.

Generated code is excluded from all linting. Don't add linting overrides to generated files - they'll be lost on the next regeneration.
